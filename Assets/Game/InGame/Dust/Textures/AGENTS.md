lost the original A/B: the Sampler set read as orange sandpaper and the Poly Haven set was uniform
mud. Both are kept only until that choice is settled — delete them then, they are otherwise dead
weight.

> **some content is licensed for Unreal Engine only** — `tdsmeeko.json` even ships a

> actual tier. If either does not permit it, that material has to go.
>
> The risk compounds: the sand was brought in on the precedent set by the dirt, so a single bad
> answer on the Fab tier takes out both contamination types at once. Settle this before authoring
> a third.

**Default to CC0.** Anything with redistribution limits — textures.com and the like — does not come
into this repository. Record source and license here *before* importing, not after.

**Substance 3D Assets are an exception that needs deciding, not assuming.** The Substance library
(the same one behind Painter's shelf) is `.sbsar` and Sampler opens it directly, so it is an easy
source — but those assets are **licensed through the Adobe subscription, not CC0**. If one is used,
record which asset and note that the licence is tied to an active subscription. Do not file it in
the CC0 row.

`T_Dirt_Normal` is the OpenGL-convention normal (`nor_gl`), which is what Unity expects. It ships as
PNG rather than JPG because JPG ringing is plainly visible in a normal map tiled 16×.

## Generated

`docs/images/generate_dust_textures.py` produces these, re-runnably, from pure stdlib. All tile.

| File | Purpose |
|---|---|
| `T_Dust_DissolveNoise` | Compared against the mask to decide what comes off. Not an alpha |
| `T_Dust_Mask_Uniform` | Fully dirty — isolates dissolve behaviour from mask shape |
| `T_Dust_Mask_Blotchy` | Uneven natural coverage |
| `T_Dust_Mask_Path` | A wiped stroke, for judging the edge of a swept path |
| `T_Dust_Mask_Corner` | Heavier towards the edges |

The masks stand in for the painting system landing next branch. Once a `RenderTexture` fills the
`_DirtMask` slot they stay only as fixtures for this test scene.

`T_Floor_Tile` is a generated mint/off-white checker. The clean floor needs a pattern that is
legible enough to be visibly *lost* under dirt — a flat colour makes the before/after read as a
tint change rather than as coverage.

`docs/images/generate_particle_sprites.py` produces the sparkle sprites, same conventions.

| File | Purpose |
|---|---|
| `T_Sparkle_Star4` | 4-point twinkle for `VFX_CleanSparkle` |
| `T_Sparkle_Star6` | 6-point variant of the same |

**RGB is uniformly white; the shape lives only in the alpha.** That way one texture works under
Additive and under Alpha Blend, and the particle's colour stays the graph's decision.

**Procedural rather than generated by a model, unlike `T_DustGrain_Particle_*` (2026-08-13).** A
star is a geometric shape, so a formula gives a cleaner alpha than an image model — and it carries
no licence question, which matters in a folder that already has two unconfirmed Megascans sets.
Grain was the opposite case: irregular organic debris, where the model was the right tool.

**The spikes are windowed to zero before the border.** Exponential falloff alone leaves a few
percent of alpha at the texture edge, and a sprite clips that into a straight line — the spikes
end as if cut with a knife. A `smoothstep` between r 0.72 and 0.98 forces it to 0; both files
measure 0/255 along the whole border.

## Import settings

These are not defaults and matter:

- `T_Dirt_Normal` — Texture Type **Normal map**
- every mask, the dissolve noise and the roughness map — **sRGB off**. They carry values, not
  colour, and the sRGB curve would bend them
- all **tiling** maps — Wrap **Repeat**
- `T_Sparkle_*` — Wrap **Clamp**, and `alphaIsTransparency` **on**. A particle sprite is not a
  tiling map: under Repeat the star wraps and the spikes reappear on the opposite edge. These are
  set by `set_import_settings`, not by the Task 2 script below, which only covers the surface maps

`docs/plans/2026-08-11-dust-surface-shader.md` Task 2 has the script that applies these.
