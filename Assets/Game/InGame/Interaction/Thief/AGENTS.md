# InGame/Interaction/Thief — 선물 절도 NPC

의뢰 실패 뒤 해당 의뢰의 집 주변에서 지연 생성되어 물리적으로 놓인 `Gift` 하나를 훔치고,
생성 위치로 돌아가는 독립 NPC다.

## 경계

- 보관소 프리팹·컴포넌트·이름·계층·슬롯·문 API를 참조하지 않는다.
- `ThiefRaidSite`가 제공하는 Collider 영역과 접근점만 안다. 보관소가 교체되면 씬의 이 어댑터만 옮긴다.
- 실제 바닥 선물은 공용 `Gift.All`에서 찾고 소유자 기반 `Gift.TryClaim`으로 펭귄과 경쟁한다.
- 실패한 의뢰와 같은 선물 단계를 먼저 찾는다. 없으면 바로 다음 상위 단계부터 차례대로 찾으며,
  실패 의뢰보다 낮은 단계의 선물은 훔치지 않는다. 단계는 `EGiftBoxKind`의 직렬화 순서인
  빨강(최상) → 노랑 → 초록 → 파랑(최하)을 따른다.
- 의뢰 실패 진입점은 레거시 `RequestDirector.RequestExpired`와 SinglePlay의
  `GiftDeliveryDirector.OrderFailed`를 모두 지원한다. 다른 시스템은 `ThiefDirector.EnqueueRaid`를
  직접 호출할 수 있다.
- `Interaction/Npc` 타입·프리팹·행동 트리에 런타임 의존하지 않는다. 서버 권위와 Behavior Designer
  패턴만 독립 구현으로 가져왔다.
- 소리 인지는 없다. 플레이어의 실제 펭귄 오브젝트에 대한 시야각·거리·차폐만 사용한다.

## 행동 우선순위

```
Repeat
└─ Reactive Selector
   ├─ ImpactReaction → 넘어지고 일어난 뒤 빈손으로 퇴장
   ├─ Escaping → 생성 위치로 귀가하고 5초 카운트다운 뒤 퇴장
   ├─ Spotted(미선점) → 습격을 포기하고 귀가 시작
   ├─ ClaimedGift → 접근하고 들어 올리기
   └─ 습격 영역으로 이동하고 선물 선점
```

시야 반응(Wary 웅크림, Spotted 달리기·우회)은 대부분 목적을 바꾸지 않는 이동 오버레이다.
`ThiefPlayerSensor`가 가시성으로 0~1 인지도를 갱신해 `Calm/Wary/Spotted` 3단계로 분류한다 —
시야에 들어오거나(10m·시야각) 5m 안으로 근접하면 즉시 Wary/Spotted로 올라가지만(순간 반응 유지),
벗어나면 인지도가 서서히 줄어야 단계가 내려가 5m 경계선을 오갈 때 자세가 매 프레임 깜빡이지
않는다. 평소(Calm)에는 달리고, Wary(먼 시야)에는 웅크려 접근한다. Spotted(5m 이내 또는 그 감쇠
유예 중)에는 다시 달려 벗어나며 우회 지점을 갱신한다. **다만 아직 선물을 선점하지 않은 상태에서
Spotted에 도달하면 예외적으로 행동 트리 우선순위 가지(`IsThiefSpotted`)가 습격 자체를 포기하고
귀가로 전환한다** — 선점 이후에는 이 가지가 개입하지 않고 계속 시도한다. 선물을 들면 항상
달리되 계속 플레이어를 우회한다. `EThiefGait.Walk`는 호환용 enum 값만 남기며 런타임에서는
선택하지 않는다.
`ThiefMovement`는 마지막으로 Spotted였던 위치를 `_threatMemorySeconds`(기본 4초) 동안 기억해
회피 지점 재계산에 계속 쓴다 — 완전히 시야를 잃거나 다시 Calm으로 가라앉아도, 그 시간 동안은
직선 대신 마지막 목격 지점을 피하는 우회를 이어간다. 긴 귀가 여정 초반에 한 번 들켰다고 남은
구간을 위험 지점 옆으로 직선 복귀하는 일을 막는다. 기억 창이 끝나면 즉시 직선 경로로 돌아간다.
빈손으로 퇴장할 때도 도망 상태에서는 항상 달린다. 집마다 한 도둑만 동시에 활동하며, 생성 위치는
실패한 집의 문 주변 NavMesh에서 무작위로 고른다. 생성 위치에 도착하면 이동을 멈추고 머리 위 숫자로
5초를 센 뒤, 도둑과 훔친 선물을 함께 제거한다. 카운트다운은 서버가 판정하고 클라이언트에는 남은
시간만 복제한다. 대기 중 플레이어 접근은 카운트다운을 취소하거나 초기화하지 않는다.

일반 물리 충돌은 `ImpactMomentum`의 운동량이 140 kg·m/s 이상일 때만 넘어뜨린다. 30kg 펭귄의
평지 걷기(3.5m/s, 약 105)는 지나가고 달리기(5.5m/s, 약 165)는 통과하는 초기값이다. 펭귄의
직접 공격은 의도된 행동이므로 운동량 문턱과 무관하게 넘어뜨린다. 넘어질 때 선점·들기·운반을
취소하고, 이미 붙인 선물은 Collider와 Rigidbody·중력을 복구한 뒤 최대 3m/s로 밀어 떨어뜨린다.
넘어져 있는 동안 추가 타격은 무시하고, 일어나면 같은 선물을 다시 집지 않고 빈손으로 퇴장한다.
생성 위치의 퇴장 카운트다운에 들어간 뒤에는 타격을 무시해 타이머 초기화를 막는다.

## 권위와 표현

- 지연 큐, NavMesh, 시야, 선점, 이동, 절도와 despawn은 서버 또는 Runner 없는 단독 모드만 수행한다.
- `ThiefNetworkHub` 한 곳이 행동·gait·화물 유무와 들어 올리기·충격 단계 및 진행률을 복제한다.
- Animator와 Final IK는 표현이다. Final IK가 없거나 헤드리스여도 절도 판정은 진행한다.
- `ThiefExitCountdownView`는 복제된 남은 시간을 숫자 `5`부터 `1`까지 표시하는 빌보드 표현이다.
  카메라가 없는 전용 서버에서는 아무것도 표시하지 않는다.
- Final IK는 predefined assembly에 있어 `PPack.InGame`에서 직접 참조하지 않고
  `ThiefFinalIkAdapter`가 반사 결과를 캐시한다. 벤더 파일은 수정하지 않는다.

## 자산

`PPack/Thief/Rebuild Thief Assets`가 Synty 샘플 컨트롤러의 도둑 전용 복사본을 바탕으로
들어 올리기 상태를 보강하고, 행동 트리, `PF_Thief`, `PF_ThiefRaidRig`를 재생성한다. 기존
`AC_Thief`는 재빌드할 때 교체하지 않으므로 수동 튜닝을 보존한다. 이동과 자세 전환은 Synty
클립을 직접 참조한다. 선물을 집는 동안 기본 몸통·머리는 중립 자세를 유지하고, Humanoid로 가져온
`Picking Up.fbx`를 양팔·손가락 Avatar Mask 레이어에만 3.5배속으로 재생한다. Final IK는 몸통과 발을
당기지 않는다. 바닥에 손을 뻗을 때는 애니메이션을 주동작으로 쓰고 낮은 손 가중치로만 보정한 뒤,
선물이 몸 가까이 들리는 동안 손 가중치를 100%까지 올린다.
바닥에 있는 동안 손 목표는 선물 `BoxCollider`의 양옆 바깥면에 두고, 들어 올린 뒤에는 손바닥이
선물 아래쪽을 받치도록 옮긴다. 팔꿈치는 상자 앞·바깥으로 유도해 손과 아래팔이 상자 내부로 관통하지
않게 한다. 들어 올리기 시작 때 캡처한 골반·발 기준을 전체 단계에서 재사용해
단계 전환마다 캐릭터 루트 높이가 누적 상승하지 않게 한다.
도둑은 선물 중심으로 이동하지 않는다. `GrabStandPosition`은 선물의 현재 회전·크기에서 도둑 쪽
표면을 구한 뒤, 도둑 캡슐 반경과 25cm 여유를 더한 발 위치다. 이 위치와 정면 정렬을 모두 만족해야
들기 단계로 넘어간다. 가슴·머리 위 선물 자세도 같은 콜라이더 형상으로 계산해 몸과 겹치지 않는다.
`PF_ThiefRaidRig`의 LootVolume과 ApproachPoint만 실제 보관소에 맞춘다.

`Animations/Nervously Look Around.fbx`는 사용자 제공 원본이지만 현재 범위에서는 사용하지 않는다.
충격 반응은 Creative Characters의 `Death_Backward`를 앞으로 재생해 넘어지고, 끝 자세를 유지한 뒤
같은 클립을 역재생해 일어난다. Root Motion은 끄고 NavMesh 루트는 세워 둔 채 전신 본만 움직인다.
충격 단계에서는 선물 집기 팔 레이어와 Final IK 가중치를 즉시 0으로 내려 떨어진 선물을 계속
따라가지 않게 한다. 별도 Mixamo 클립을 추가할 때도 이 상태 계약은 유지한다.
