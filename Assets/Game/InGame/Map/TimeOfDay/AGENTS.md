# InGame/Map/TimeOfDay — 하루 주기 하늘

플레이 시간을 하루로 환산해 해·스카이박스·안개·앰비언트를 굴린다. 맵이 소유하는 이유는 이것이
**환경 연출**이기 때문이다. 어느 맵에 얹든 동작하고, 어느 게임 규칙도 참조하지 않는다.

## 구성

| 파일 | 역할 |
|---|---|
| `Scripts/TimeOfDayConfig.cs` | SO. 하루 길이와 시간대별 색·세기 곡선 전부 |
| `Scripts/TimeOfDayDirector.cs` | 씬에 하나 두는 컴포넌트. 시간을 세고 환경에 칠한다 |
| `Scripts/EDayPhase.cs` | Night/Dawn/Day/Dusk — 그라디언트에서 파생된 이름표 |
| `Scripts/StarDome.cs` | 밤하늘의 별. 카메라를 따라다니는 뒤집힌 구 |
| `Shaders/StarDome.shader` | 별 전용 가산 셔이더. 안개 항이 없다 |
| `Textures/T_TimeOfDay_Starfield.png` | 4096×2048 적도투영 별하늘. 검은 배경, 좌우 이음새 없음 |
| `Data/TimeOfDay_Default.asset` | 기본 프리셋. 씬 빌더가 없으면 만든다 |

## 하루 길이는 `SecondsPerDay` 하나다

기본 300초(5분). `Data/TimeOfDay_Default.asset`에서 바꾸면 되고, **플레이 중 바꿔도 즉시 반영**된다
— 디렉터가 매 프레임 SO를 읽는다. `StageBalanceConfig`와 같은 이유, 같은 방식이다. 확정값은 프리셋
에셋으로 굳힌다(`.asset`은 YAML이라 Plastic이 병합하지 못하므로 프리셋 하나당 파일 하나).

시간은 0~1 정규화다. `0 = 자정`, `0.25 = 일출`, `0.5 = 정오`, `0.75 = 일몰`. 모든 그라디언트·커브의
가로축이 이 값이다.

## 지켜야 할 것

- **스카이박스 에셋을 직접 칠하지 않는다.** 디렉터는 `new Material(template)`로 런타임 복제본을
  만들어 `RenderSettings.skybox`에 꽂고, 파괴 시 원본 스카이박스·안개·앰비언트를 되돌린다. 에셋을
  직접 만지면 플레이를 끝내도 값이 남아 맵의 블루아워 라이팅 원본이 오염된다.
- **게임 규칙을 모른다.** 의뢰·점수·전역 타이머를 참조하지 않는다. Map이 Cleanliness를 알면 안 되기
  때문이다. 진행을 게임 페이즈에 묶고 싶으면 바깥에서 `Begin()`/`Pause()`를 부른다(`_autoStart`를
  끄고).
- **스카이박스는 반드시 `Skybox/Procedural`이어야 한다.** 맵이 씬에 꽂아둔 건
  `M_Everest_BlueHourSky`(**`Skybox/Cubemap`**)라 `_SkyTint`·`_Exposure`·`_SunSize`가 아예 없다.
  그대로 두면 `HasProperty`에 전부 걸려 **조용히 아무것도 안 하고**, 해도 달도 뜨지 않는다. 그래서
  `SkyboxTemplate`에 `WinterVillage/Lighting/Materials/M_WinterVillage_BlueHourSky.mat`를 꽂아 둔다.
  구워진 큐브맵은 고정된 사진이라 하루 주기가 원리적으로 불가능하다. 산맥은 큐브맵이 아니라 실제
  메시(`MSH_Everest_*`)라 바꿔도 그대로 남는다 — 확인했다.
- **해와 달은 원반 주인을 교대한다.** 절차적 스카이박스는 `RenderSettings.sun` **하나만** 보고 원반을
  그린다. 밤에 그 자리를 달에게 넘겨야 하늘에 달이 뜬다. 원본 머티리얼은 `_SUNDISK_NONE`이므로
  런타임 복제본에서만 원반을 켜고, `RenderSettings.sun`도 복원 대상이다.
- **별은 URP Unlit으로 못 그린다.** 두 번 데였다. (1) 플로트만 바꾸고 키워드를 빼먹으면 머티리얼이
  불투명으로 남아 돔이 깊이를 써버리고, 스카이박스가 아예 안 그려져 **낮 하늘이 검게 죽는다**.
  (2) 고쳤더니 이번엔 안개가 별을 먹는다 — 반지름 450m에서 가시도가 **0.00028**이었다(측정값).
  URP의 안개 키워드는 전역이라 머티리얼 단위로 못 끈다. 그래서 안개 항이 없는 `PPack/StarDome`
  셰이더를 따로 둔다.
- **하늘 텍스처는 각도로 생각한다.** 적도투영에서 `v=0`은 천정, `v=0.5`가 지평선,
  고도 = `(0.5 - v) x 180deg`이고 커튼 하나의 폭 = `반폭_u x 720deg`다. 처음 만든 오로라는
  고도 **-13도~+83도에 폭 72~108도** — 시야각(60도)보다 넘어서 먼 하늘이 아니라 가까이 붙은
  벽지처럼 보였다. **누워서 밴드로 앜혀야 하늘이 멀어진다**(지금 +2도~+45도). 단, 커튼을
  가늘게 쪼개면 빗자루처럼 보인다 — **모양은 크고 부드럽게 두고 위치만 낮춘다.**
  텍스처 상단 8%가 비어 있어야 돔 꼭대기에서 잘리지 않는다.
- **별은 작고 촌초하게, 플레어 없이.** 크고 반짝이는 십자 플레어는 가까운 파티클처럼 보인다.
  8192x4096에 26,000개, 밝기는 `균등^3.2`(밝은 별은 소수), 코어 0.7px 가우시안에 가장 밝은
  별만 2.4px 헤일로. 점을 뿌릴 땐 `arccos(1-2u)/pi`를 써야 한다 — 균등하게 뿌리면 극지방에 뻓친다.
- **밤하늘 텍스처에는 성운이 같이 구워져 있다.** 별 돔이 이미 가산 합성이므로 성운을 같은
  텍스처에 합성하면 **드로콜이 늘지 않는다.** 세기는 레퍼런스 스크린샷의 통계에 맞췄다 —
  평균 휘도 0.036(레퍼런스 0.059), 평균 RGB가 파랑 우세. 이보다 올리면 솔솰처럼 보인다.
- **수평선 색은 `_AtmosphereThickness`가 지배한다.** 두꺼울수록 노랑→초록으로 밀린다. 측정값:
  1.05에서 녹색 초과 **+6.2**, 0.55에서 **−10.8**. 낮은 얇게 가져간다.
- **노을은 해가 지기 전에 넣는다(`DuskStart = 0.68`).** 해가 지평선 아래로 내려가면 절차적 하늘은
  따뜻한 산란을 만들 재료가 없어 황갈색으로 탁해진다. `t=0.73`에서 지는 해가 보인다.
- **전환의 끊김은 셰이더 배리언트 컴파일이다.** 배리언트는 **처음 그려질 때** 컴파일된다.
  별·오로라·달 원반·해가 전부 해질녘에 `enabled`를 뒤집어서 컴파일이 한 프레임에 몰렸다.
  `SkyDome`과 `MoonDisk`는 첫 몇 프레임(`_warmFrames`)을 **검은색으로라도 그려** 로딩 중에
  컴파일을 끝낸다. 가산 합성이라 검은색은 화면에 아무것도 더하지 않는다.
- **불리언 컷오프는 팝 터진다.** 달 원반은 예전에 `_direction.y > -0.05f`로 끊겨서 지평선을
  넘는 순간 깜빡하고 사라졌다. 가시성은 전부 `SmoothStep`으로 죽인다.
- **밤 밝기를 지배하는 것은 `MoonIntensity` 다.** 앤비언트를 절반으로 낮춰도 눈/하늘 대비가
  2.9 → 2.8 배로밖에 안 움직였다. 반대로도 확인했다 — 밤이 너무 어둡다는 피드백을
  **`MoonIntensity` 0.34 → 0.62** 로 해결했고, 그림자가 새까맣게 되지 않게 앤비언트도
  0.13/0.16/0.27 로 조금 올렸다.
- **창문 Bloom 은 이미 동작하고 있었다 — 모자란 건 세기뿐이다.** 맵이 소유한
  `WinterVillage_LightingProfile` 에 Bloom 이 살아 있고, 카메라는 postFX·HDR 둘 다 켜져 있으며,
  밤 창문 emission 은 **6.47** 로 문턴(0.74)을 한참 넘는다. "Bloom 을 넣어달라"는 요청에
  새로 만들 것이 없었고, intensity 0.68 → 1.45 / threshold 0.74 → 0.62 / scatter 0.72 로
  올리기만 했다. **뭐가 없다고 단정하기 전에 프로파일을 먼저 읽을 것.**
  `WarmWindowLight` 가 `MaterialPropertyBlock` 으로 `_EmissionColor` 를 바꾸지만 머티리얼의
  `_EMISSION` 키워드는 그대로라서 Bloom 이 먹는다.
- **밤 앤비언트가 높으면 하늘이 가깝게 느껴진다.** 밝은 지면과 어두운 하늘이 맞닿으면 깊이가
  죽는다(측정: 밤 하늘 0.225 대 눈 0.643, **2.9배**). 달빛은 두고 앤비언트만 낮춘다.
- **새 필드를 추가하면 기존 프리셋 에셋에서는 0으로 들어온다.** 필드 이니셜라이저는 이미 직렬화된
  에셋에 적용되지 않는다. 실제로 원반 크기가 0이 돼서 해도 달도 안 보였다. **값을 추가했으면
  `ApplyDefaultSky()`에도 같이 넣고**, 기존 에셋에 컨텍스트 메뉴 `기본 하늘 값 채우기`를 한 번 돌린다.
- 밤에 세기 0인 해는 **꺼진다**. 지평선 아래 디렉셔널 라이트를 켜 둔 채로 두면 URP가 계속 그림자를
  갱신한다.
- 앰비언트는 SO 그라디언트가 원본이다. `DynamicGI.UpdateEnvironment()`는 부르지 않는다 — 매 프레임
  돌리기엔 비싸고, 어차피 앰비언트 색을 직접 넣고 있다. 씬의 Environment Lighting을 Skybox로 바꾸면
  이 전제가 깨진다.

## 씬에 넣는 법

`PPack/Cleanliness/Build SinglePlay Scene`가 `SnowDeliveryRig/TimeOfDayDirector`로 자동으로 넣는다.
손으로 넣을 때는 빈 오브젝트에 `TimeOfDayDirector`를 붙이고 `_config`만 꽂으면 된다. `_sun`을 비워
두면 `RenderSettings.sun` → 씬의 첫 디렉셔널 라이트 순으로 찾는다.

## 아직 없는 것

- 에디트 모드 미리보기. 지금은 Play를 눌러야 하늘이 움직인다. `[ExecuteAlways]`를 붙이면 씬의
  RenderSettings를 편집 중에 덮어써 씬이 dirty가 되므로 일부러 넣지 않았다. 필요해지면 슬라이더 +
  복원 버튼이 있는 커스텀 에디터로 만든다.
- 밤 전용 연출 훅(가로등 점등, 창문 emissive). `PhaseChanged`/`DayAdvanced` 이벤트는 이미 나오므로
  구독자를 만들면 된다 — 두 번째 소비자가 생기면 그때 공통 리스너를 만든다.
