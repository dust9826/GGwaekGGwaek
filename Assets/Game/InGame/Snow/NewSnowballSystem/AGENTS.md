# NewSnowballSystem — 눈덩이 성장 런타임과 검증 씬

이 폴더는 Seed에서 4단계까지 반지름을 4등분한 성장, 실제 크기 추적 HUD, Feel 팝의 런타임 코드와 격리 검증 씬을
함께 소유한다. 검증된 성장 컨트롤러와 HUD는 `Cleanliness/Scenes/SinglePlay.unity`에도 적용된다.

- 기존 `Snow/Resources/PF_SnowBall.prefab`, `SnowBallCarrier`, 게임 씬과 현재 HUD를 수정하지 않는다.
- 테스트 씬과 테스트 프리팹은 이 폴더가 소유한다.
- 플레이 테스트 씬은 `Snow/Tests/Snow_BallPush_Test.unity`의 실제 펭귄·눈 필드를 복사해 사용한다.
- 복사한 테스트 펭귄과 프로덕션 SinglePlay는 `PenguinMomentumHandling`과
  `PenguinMomentumSnowballBinder`를 사용해 같은 단계별 밀기 법칙을 공유한다.
- 실제 공의 루트 스케일·콜라이더·자식 렌더 프록시·설면 수확 반폭은 항상 같은 제어 반지름을 사용한다.
  단계 반지름 증가분의 40%는 수확 진행도에 따라 연속 성장하고, 나머지 60%는 승급 순간 실제 반지름·충돌체·질량이
  함께 점프한다. Feel 팝은 이 물리 크기 변화를 강조할 뿐 대신하지 않는다.
- Seed→1, 1→2, 2→3, 3→4 기준 시간은 테스트 씬 컨트롤러의 네 직렬화 값이 각각 소유한다. 기본값은
  모두 7초다. 이 값은 타이머가 아니라, 300 mm 처녀설을 해당 단계 진입 최고속도로 그 시간 동안
  지날 때 얻는 양으로 단계별 고정 필요량을 계산하는 기준이다.
- 성장 진행도는 `SnowCpuStage`의 단일 스윕이 필드에서 실제로 제거한 원시 눈의 양(mm·셀)을 누적한다.
  현재 셀 깊이를 그대로 읽으므로 발자국으로 50 mm가 먼저 사라졌거나 같은 길을 다시 지나면 남은
  눈만 반영된다. 필요량을 넘긴 수확분은 다음 단계로 이월한다.
- 수확된 원시 눈은 Rigidbody 질량으로 직접 더하지 않는다. 단계 진행에는 제거량 100%를 쓰고,
  `SnowBallCpu`의 내부 취득 질량은 기존 `growthWeight=0.5`를 유지하며, 조작용 Rigidbody 질량은
  제어 반지름에서 계산한 균일 밀도 구체 법칙만 따른다.
- 관성 실험용 유효 질량은 균일 밀도 구체 법칙 `m = 300(r / 1.5)³`을 사용한다. 최소
  `0.5184 kg`, 최대 `300 kg`이고 단계는 질량을 바꾸는 스위치가 아니라 반지름 표시 구간이다.
- 밀기 조작은 Seed·1/2/3/4단계 진입의 다섯 파라미터 점에서 속도·가속시간·조향
  반응시간을 실제 반지름 진행도로 보간한다. 단계는 HUD/시각 구분만 소유하고 경계에서 값이 끊기지 않는다.
- 눈덩이 최고속도는 최소 반지름 3.2 m/s에서 최대 반지름 5.0 m/s까지 증가한다. 걷기 3.5 m/s와
  달리기 5.5 m/s를 넘지 않는다. 조향 반응시간은 0.35초에서 3초까지 증가한다.
- W를 놓으면 추진 누적은 0.2초에 해제하지만 눈덩이 속도를 직접 지우지 않는다. 자연 감속·S 제동·
  조향은 최대 반지름 기준 힘을 반지름²으로 환산하고, 질량은 반지름³으로 증가한다. 따라서 작은 공은
  즉시 멈추고 방향을 바꾸지만 큰 공은 실제 운동량 때문에 더 오래 굴러가고 같은 입력으로 덜 꺾인다.
- 눈덩이 조향량은 반지름에 따라 방향전환 직후·완전 누적 상한을 각각 직선 보간한다. 각 진입점의
  기준 최고속도에서 Seed는 `64.6% / 74.4%`, Stage 1/2/3은 `48.5/64.1%`,
  `32.3/53.7%`, `16.2/43.4%`, 최대 Stage 4는 `0% / 33%`다. 여기에 0 m/s와 9 m/s의
  전역 속도 계수를 곱하며, 9 m/s를 넘어도 0이 될 때까지 같은 기울기로 감소한다.
- Seed HUD 진행도는 타이머가 기억한 실제 생성 반지름에서 0%로 시작한다. 4단계는 최대 반지름
  `1.5 m`에서만 진입하며 즉시 완료 상태가 된다.
- 단계 판정과 표시 반지름은 실제 반지름을 읽는다. HUD 진행도는 단계별 실제 수확량 비율을 읽어 실제
  반지름이 승급 직전 40% 지점에 있어도 100%까지 채워진다. 단계 경계에서도 표시·콜라이더·밀기
  궤도 사이에 영구적인 크기 차이를 만들지 않는다.
- 기본 크기는 `StageSizePivot`, 일시적인 Feel 스케일은 그 자식 `StagePopFeedbackPivot`만 소유한다.
- 실제 플레이용 렌더 프록시는 이전·현재 물리 반지름을 렌더 프레임마다 보간한다. 루트 스케일과
  콜라이더는 물리 반지름을 그대로 유지하며, 보간 지연은 한 물리 틱을 넘지 않는다.
- `SnowCpuStage`는 표시·콜라이더와 같은 제어 반지름을 `SnowBallCpu`의 기존 띠 스윕에 직접 전달한다.
  따라서 실제 공 지름과 제거 폭은 격자 한 칸 오차 안에서 같고, 별도의 양옆 추가 절삭은 하지 않는다.
- Stage 4는 반지름 `1.5 m`와 조작용 질량 `300 kg`에서 더 커지지 않지만, 같은 1.5 m 반폭으로
  설면 제거와 내부 취득 질량 장부는 계속 처리한다.
- 실행 순서는 `SnowCpuStage(0) → SnowballGrowthFootprintSync(25) → SnowballGrowthStageTimer(50) → SnowballMomentumMass(75) →
  SnowBallCarrier(100)`이다. 수확량을 읽은 뒤 제어 반지름과 유효 질량을 추진 전에 확정하므로
  성장 씬도 기존 `SubmitPush` 하나만 추진 경로로 사용한다.
- HUD는 현재 단계 하나만 그리고, 눈덩이 화면 반지름에서 곡률을 계산한다.
- 테스트 씬은 Build Settings에 넣지 않는다.
- `Tests/Scripts/SnowballGrowthPlayableSceneController`는 테스트 전용 asmdef 밖의 `PPack.InGame`
  코드이며 테스트 씬과 SinglePlay가 함께 사용한다. 테스트 전용 드라이버와 씬 조립 코드는
  `Tests/`·`Editor/`에 남긴다.
