# InGame/Tutorial — 실제 조작을 배우는 펭귄 훈련장

이 폴더는 별도 튜토리얼 씬과 그 씬의 단계 진행·안내 UI만 소유한다. 이동, 슬라이딩,
눈덩이, 운반의 규칙을 복제하지 않고 각각 `PenguinLocomotion`, `PenguinSnowball`,
`SnowCpuStage`, `PenguinCarry`가 공개하는 실제 상태를 관찰한다.

- 프로덕션 씬: `Scenes/PenguinTutorial.unity`
- 메인 메뉴의 Tutorial 버튼은 `Scenes/PenguinTutorial.unity`를 연다. 이 훈련장은 여덟 단계 흐름을 유지하되
  이동 피로가 생기지 않도록 적설 바닥을 최대 64×48m로 제한하고, 인접 단계 출입구를 한 화면 안에서
  읽을 수 있게 배치한다. `TutorialPlay`와 혼동해 수정하지 않는다.
- `PenguinTutorial`은 야외 마을이 아니라 눈 선물 기계와 같은 청록·분홍 색상의 산타 공장 실내 훈련장이다.
  눈덩이 굴리기를 위해 적설 바닥은 유지하고, 외벽·기둥·상부 창·천장 트러스·펜던트 조명은 플레이 공간
  바깥에 둔다. 배관과 상자는 외벽에 붙이며 걷기·달리기·슬라이딩·눈덩이 운반 동선을 막지 않는다.
- 단계 출입구의 체크포인트 기둥과 낮은 구획 벽은 끝점을 공유하지 않는다. 벽 몸체뿐 아니라 더 넓은 눈 덮개가
  화살표·기둥을 관통하지 않도록 각 기둥 주위에 최소 0.9m의 빈 구간을 두고, 모든 출입구에 같은 기준을 적용한다.
- 여섯 실내 구역은 걷기·달리기·슬라이딩·눈덩이·제작·배송을 공간별로 대표하고, 배송 구역 안에서
  창고 인출과 옆 배송처 납품까지 이어지는 여덟 단계 사이클을 완성한다. 실제 완료 판정을 받는
  택배 발송기는 6번 배송 구역 안에 두고, 5번 제작 구역에는 눈 선물 기계만 남긴다. 각 구역의 번호·행동 표지와
  색상 바닥 유도선은 입구에서 구역 성격을 읽게 하되 콜라이더 없이 배치한다. 메인 메뉴에서 연결되는
  `PenguinTutorial`은 월드 화살표·떠 있는 목표 표식·화면 가장자리 방향 화살표를 표시하지 않고, 좌측 상단
  퀘스트 카드의 제목·키·설명·진행도만으로 다음 행동을 안내한다. 체크포인트 기둥의 입체 화살표와 바닥
  셰브론도 만들지 않으며, 상단 단계 바와 우측 하단 조작표 역시 숨긴다.
- 눈덩이 단계는 씬 시작 시 눈덩이를 미리 만들거나 Director가 자동 생성하지 않는다. 플레이어가 적설 위에서
  실제 `PenguinSnowball` 입력 E를 눌러 발밑 눈을 뭉쳐 새 눈덩이를 만든 뒤 굴려야 한다. 생성 위치에는
  최소 3×3m의 읽기 쉬운 눈 패치를 두고, 기본 눈덩이 성장 가중치로도 첫 시도가 충분한 질량을 얻어야 한다.
  실패하면 즉시 좌측 HUD 문장과 패치 파티클로 재시도 위치를 알려 준다.
- 배송 구역에는 플레이어가 선물을 밀어 넣는 우편 발송기 한 대와 실제 창고 한 채만 보인다. 같은 채널의
  수신 단말기는 배송 로직을 위해 창고 내부에 렌더러·콜라이더·오디오가 꺼진 엔드포인트로 두며,
  별도의 두 번째 배송 기계처럼 노출하지 않는다.
- `PenguinTutorial`의 단계 순서는 걷기 → 달리기 → 슬라이딩 → 눈덩이 만들고 굴리기 → 제작기에 넣기 →
  우편 단말기로 보내기 → 4색 창고에서 꺼내기 → 옆 배송처 패드에 납품하기다. 좌측 HUD는 항상 `1 / 8`부터
  `8 / 8`까지 실제 상태를 표시하고, 마지막 납품 뒤 완료 카드를 보여 준 다음 메인 메뉴로 돌아간다.
- 씬 생성기: `Editor/PenguinTutorialSceneBuilder.cs`
- 전체 물류 플로우 확인 씬: `Scenes/GiftProductionDeliveryFlow.unity`. 눈덩이 투입 → 선물 생성 →
  독립 우편 단말기 배송 → 창고 자동 진열 → 아래 선물 인출 → 위 배송 선물 낙하/재인출을 한 공간에서
  실제 게임 컴포넌트로 확인한다. 재생성은
  `PPack/Tutorial/Build Gift Production Delivery Flow Scene` 메뉴를 사용한다.
- 창고의 네 중력 레인은 왼쪽부터 파랑(1단계)·초록(2단계)·노랑(3단계)·빨강(4단계) 전용이다.
  각 레인은 아래 픽업칸과 위 예비칸만 공유하며, 같은 색 레인이 가득 차도 다른 색 칸에 섞지 않는다.
- 창고 정문에는 바깥 적설 앞마당에서 문턱을 넘어 내부 바닥으로 직접 이어지는 넓은 진입 경사로가 있다.
  펭귄과 발로 미는 선물이 걸리지 않도록 45도 보행 한계보다 충분히 완만하고, 보이는 경사면 자체가
  Collider를 소유해야 한다. 지붕으로 올라가는 외부 경사로는 두지 않는다.
- 시작 컷신: 펭귄이 눈을 기계에 넣음 → 눈 요정이 얼음을 장난감으로 조각함 → 산타가
  얼음 조각을 실제 선물로 바꿈 → 요정이 포장하고 자판기처럼 배출함. 액자형 만화 카드는
  클릭할 때마다 한 장씩 진행하며, 왼쪽·오른쪽 카드는 서로 겹치지 않는 맞물린 프레임에 표시한다. `ESC`로
  전체 컷신을 건너뛴다. 모든 컷신 `UIDocument`는 런타임용 `PanelSettings`를 반드시 저장하고 검증한다.
- 시작 컷신과 배송 흐름 컷신은 별도의 `START STORY` 확인 화면을 띄우지 않고 첫 카드를 즉시 보여 준다.
  카드가 멈춰 있을 때에는 `CLICK ▶ NEXT`를 계속 표시하며, 한 번의 클릭으로 정확히 한 장만 추가한다.
- 눈이 실제 선물로 바뀐 직후에는 배송 흐름 만화를 한 번 더 재생한다. 펭귄이 완성 선물을 독립 우편
  단말기에 발로 밀어 넣음 → 전송 VFX와 함께 사라짐 → 먼 마을의 색상별 창고에서 다른 펭귄이 같은
  선물을 꺼냄 → 그 펭귄이 해당 집 앞까지 밀어 배달함의 4카드 순서다. 반대편 택배가 현재 플레이 공간에
  즉시 나타나는 연출은 사용하지 않으며, 이 만화가 끝난 뒤 실제 `GiftDelivery` 조작 단계를 연다.
- `TutorialPlay` 퀘스트 순서: 걷기 → 달리기 → 슬라이딩 → 눈덩이 굴리기 → 눈 선물 기계 투입 →
  나온 선물을 발로 밀어 우편 배송 단말기에 넣기 → 외곽 창고에서 같은 상자 꺼내기 → 창고 옆집에 배달하기.
  퀘스트 단계는 실제 생성·배송·창고 저장·인출·납품 상태가 확인되었을 때만 완료한다.
- `TutorialPlay`에는 화면을 크게 가리는 기존 튜토리얼 카드와 단계 차단벽을 두지 않는다. 좌측 상단의 작은
  배송 일지만 진행을 기록하며, 한 사이클 완료 뒤에도 씬에 남아 자유롭게 플레이할 수 있게 한다.
  기존 `PenguinTutorial` 씬은 완료 카드를 3초간 보여준 뒤 `MainMenu.unity`로 자동 복귀한다.
- `TutorialPlay`의 산타 길라잡이는 화면 오른쪽 아래에서 단계 시작·장시간 정체 힌트·전체 완료 때만
  1~2문장으로 말한다. 중앙 플레이 화면을 가리거나 입력·카메라를 잠그지 않고, 새 단계 안내는 이전 말을
  교체한다. 텍스트만으로 모든 정보를 이해할 수 있어야 하며 녹음 음성은 같은 내용의 선택적 보강으로 둔다.
  산타의 대사는 버튼 설명을 반복하기보다 현재 세계 목표와 다음 행동의 이유를 알려 주고, 실제 게임 상태가
  바뀌기 전에는 성공했다고 말하지 않는다.
- 씬·머티리얼·프리팹 참조는 생성기를 통해 수정한다. YAML을 손으로 편집하지 않는다.
- `PenguinTutorial`의 단계 차단벽은 SF 레이저 격자를 사용하지 않는다. 알파 블렌딩한 옅은 청백색
  반투명 서리막, 드문 저속 눈송이, 빨강·크림 지팡이사탕 봉으로 구성한다. 서리막 알파는 잠금 중에도
  대략 0.15~0.22만 천천히 오가며, 반복 무늬·강한 애디티브 글로우·고밀도 눈보라를 사용하지 않는다.
  해제 때에는 옅은 금빛으로 변한 뒤 작은 눈송이 버스트와 함께 조용히 녹아 사라진다.
  실제 통과 가능 여부의 기준은 시각 효과가 아니라 `TutorialStageGate`의 Collider 상태다.
- 튜토리얼의 모든 한글 UI(좌측 퀘스트 카드 제목·설명·진행도, 컷신 대사·말풍선, 산타 길라잡이,
  조작 안내)는 튜토리얼 Quest UI와 같은 `Assets/Game/InGame/UI/MissionHUD/Fonts/Jua-Regular.ttf`를 사용한다.
  `PenguinTutorial.uss`의 `.screen` 폰트 지정을 기준으로 삼고, 명시적인 기획 변경이 없으면
  `NotoSansKR-Variable`이나 다른 한글 폰트로 대체하지 않는다. 영문 스탬프·단계 숫자·키 배지는 기존
  `LilitaOne-Regular`를 유지한다.
- 좌측 퀘스트 HUD는 단계 완료 때 Feel `MMF_Player`로 초록색 `QUEST CLEAR` 도장과 카드 펀치를 재생하고,
  다음 단계는 별도의 Feel 플레이어로 짧게 슬라이드 인한다. 진행 상태를 바꾸는 로직과 피드백 재생은 분리한다.
- 각 훈련 구역의 벽 표지판은 글자만 놓지 않는다. 인게임 펭귄의 해당 행동을 그린 정사각형 PNG,
  영문 구간명, 실제 입력 키 배지를 한 표지판 안에 함께 둔다. 아이콘 이미지에는 글자를 굽지 않고 입력 키는
  Unity 텍스트로 렌더링해 키 변경과 가독성 검증이 가능해야 한다. 걷기 `WASD`, 달리기 `SHIFT + WASD`,
  슬라이딩 `SHIFT + SPACE`, 눈 굴리기 `E → W / A D`, 기계 투입 `E → W`, 배송 `W / A D`를 기준으로 한다.
- 표지판 글자는 `RoomSignTextDepth`처럼 일반 월드 깊이를 검사해야 하며, 뒤쪽 구역의 글자가 앞쪽 간판이나
  구조물을 뚫고 보이면 안 된다. 간판은 북쪽 구조 기둥과 기계 실루엣 뒤에 놓지 않는다. 필요하면 벽에서
  앞으로 당기고 좌우 레이아웃을 뒤집은 뒤, 실제 플레이 카메라 높이에서 아이콘·제목·키가 모두 보이는지 확인한다.
- 단계 차단문 양옆의 낮은 벽은 문기둥 중심선까지 연속해서 닿아야 한다. 시각적 틈뿐 아니라 플레이어가
  퀘스트를 완료하지 않고 옆으로 우회할 수 있는 Collider 틈도 허용하지 않는다. 5개 단계 경계 모두를
  `ValidateQuestBoundaryContinuity`로 검사하며, 문 중앙의 `QuestBarrier`만 단계 완료 때 열리게 한다.
- 시작 컷신 동안만 입력과 카메라를 잠그며, 조작 단계가 시작된 뒤에는 입력을 대신 실행하거나
  플레이어 조작을 잠그지 않는다. 실제 게임 컴포넌트가 성공 상태를 만들었을 때만 다음 단계로 넘어간다.

## SinglePlay에서 검증된 마을 배치 문법

`Cleanliness/Scenes/SinglePlay.unity`의 `RoadNetwork`를 마을형 신규 심과 콘셉 아트의
기본 구조로 삼는다. SinglePlay는 21개 도로 노드와 22개 세그먼트로 만든 비대칭 도로망이며,
집 11채를 도로 노드에서 직접 떼어 놓고 짧은 진입로로 연결한다.

- 순서는 `도로 노드 → 주 가로 → 교차 연결 → 집 → 진입로 → 랜드마크 → 소품`이다.
  집이나 기계를 먼저 배치한 뒤 도로를 억지로 꾸부리지 않는다.
- 한 개의 링 로드나 바둑판 격자를 쓰지 않는다. SinglePlay처럼 북쪽 생활가로,
  동쪽 남북축, 중앙 대각선, 남서 지선의 3~4개 서로 다른 축을 2~3개 횟단로로 연결한다.
- 교차로는 가로를 방사형으로 많이 뽑는 별 모양이 아니라, 2~3개 세그먼트가 만나는
  T자·완만한 삼거리를 기본으로 한다. 접합부는 어깨면과 둥근 전환면으로 메꾼다.
- 회전된 직선 큐브를 여러 개 겹쳐 교차로를 만들지 않는다. 연결된 도로 방향의 양쪽 경계점으로
  외곽선을 만들고 곡선 보간한 전용 교차로 메시로 덮는다. `TutorialPlaySceneBuilder.CreateSmoothJunction`이
  표면과 어깨면을 따로 생성하는 기준 구현이다. 전환면 반경은 도로 폭의 약 1.5배 이내로 제한해
  교차로가 원형 광장처럼 부풀지 않게 한다.
- 주 도로 표면 아래에는 0.7~1.5m 더 넓은 다져진 눈 어깨면을 두고, 도로·진입로·눈밭의
  색과 높이를 분리해 플레이 동선이 즉시 읽히게 한다.
- 집은 연결된 도로 노드에서 대체로 7~16m 물려 놓는다. 도로가 집 외벽에 붙지 않게 하고,
  집 정면(local `+Z`)을 해당 노드로 향하게 한 뒤 폭 2~3m의 짧은 진입로로만 연결한다.
- 집을 모두 같은 간격과 각도로 놓지 않는다. 3~5채는 하나의 생활가로를 따라 헐겁게 군집하고,
  1~2채는 횟단로나 지선 끝에 따로 두어 실루엣과 플레이 리듬을 만든다.
- 집 앞은 보행·배송·선물 배치를 위해 비워 둔다. 울타리는 뒷마당과 측면만 감싸고,
  정문·진입로·선물 납품 패드를 막지 않는다.
- 제작 기계·배송기·창고는 도로 가운데가 아니라 가로 옆 서비스 마당과 짧은 지선에 놓는다.
  제작 기계는 맵 중심에서 12m 이내의 중앙 작업장에, 창고는 외곽 도로 끝에 둔다. 배송기는 그 사이의
  독립된 중간 거점으로 사용한다. 제작 기계와 창고는 최소 32m 떨어뜨려 서로 붙은 한 시설처럼 보이지 않게 한다.
- 랜드마크는 삼거리, 도로 끝, 광장에 놓아 다음 목표를 보이게 한다. 집과 랜드마크 사이에는
  10~18m 정도의 환기공간을 두고, 나무·바위·장식을 빈틈없이 채우지 않는다.
- 나무와 바위는 외곽, 집 뒤, 사각지대에 2~5개씩 묶고 도로 중앙과 집 정면은 비운다.
  가로등은 모든 간격에 균일하게 놓지 말고 교차로·커브·집 진입로·설비 마당 가장자리에 우선 배치한다.
- 램프·가로등·표지판 지주는 주 도로, 교차로 전환 메시, 집 진입로 표면 위에 절대 놓지 않는다.
  도로 가장자리에서 최소 0.9m 바깥의 눈밭·어깨면에 놓고, 플레이어와 발로 밀리는 선물의 통행 폭을 남긴다.
  신규 빌더는 직선 도로와 곡선 교차로 메시 모두에 대해 이 거리를 검증하고, 범위를 침범한 램프가 있으면 생성을 실패시킨다.
- 콘셉 아트도 같은 구조를 따른다. 하늘에서 본 도로 축 3~4개, 도로를 보는 집 정면,
  독립된 설비 마당, 의도적인 빈 눈밭이 한 눈에 읽히게 프레임을 잡고 나중에 소품을 추가한다.

`TutorialPlay` 신규에서는 위 문법을 축소해 사용한다. 특히 도로를 보는 집, 비대칭 세 가로 축,
도로 어깨면, 서비스 마당의 독립된 제작 기계·우편 단말기, 북쪽 창고를 필수 검증 항목으로 둔다.
단, 집 입구와 주도로를 별도의 직선 진입로로 연결하지 않는다. 집은 도로를 바라보되 사이 공간을
눈 덮인 앞마당으로 남기며, 실제 퀘스트 목적지에만 작은 납품 패드를 둔다.
