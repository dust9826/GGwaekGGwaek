# InGame/Vacuum — 흡입 대상의 공용 마커

차량의 흡입/당기기 기능이 공유하는 대상 마커와 그 자체의 프레젠테이션(포획 메시 변형, 사거리
진입 하이라이트)을 소유한다. 도보 청소기는 2026-08-12에 완전히 폐기됐다. `Vehicle/`이 판정과
이동을 소유하고, 이 폴더는 마커 컴포넌트만 제공한다.

## 경계

- `SuctionTarget`은 흡입 가능한 오브젝트의 마커다. 포획 중 메시 변형(스트레치)과, 조준 중(부채꼴
  사거리 진입 시)의 보라색 맥동 이미션 하이라이트(`SetHighlighted`)를 함께 소유한다 — 둘 다
  판정 결과를 받아서 그리기만 할 뿐 판정 자체는 만들지 않는다.
- 차량 타입을 이 폴더에서 참조하지 않는다. 현재 호출자는 `Vehicle/VehiclePullAbility` 하나다.
- 시각 상태는 클라이언트 프레젠테이션이다. 헤드리스 서버의 판정은 하이라이트 없이 동일하게
  동작해야 한다.

## 폴더 맵

| | |
|---|---|

| `Tests/VacuumVfxTestInput.cs` | 위 레거시 테스트 씬의 좌클릭 프리뷰 입력 — 같이 정리 대상 |

## 결정

- **도보 청소기는 폐기했다(2026-08-12).** `VacuumAimController`, `VacuumSuction`, 손에 든 모델,
  조준 UI, 캡처 인디케이터와 `Vacuum_Suction_Test`를 제거했다. 차량 프로토타입을 메인 플레이
  주체로 확정했기 때문이다.
- **VFX는 런타임 Particle System 스트릭이다(2026-08-12).** 원뿔의 반투명 면은 주행 시 화면을
  넓게 가리므로 사용하지 않는다. 원뿔 내부 임의 지점에서 노즐로 이동하는 늘어난 파티클로
  범위와 방향을 동시에 읽게 한다. 포획 중에는 대상 위치에서 별도 스트릭이 모이고, 수거 시
  노즐에서 짧은 펄스가 발생한다.
- **스트릭은 판정 원뿔을 강체처럼 따라가지 않는다(2026-08-12).** 원거리 생성 방향은 노즐
  회전을 늦게 따라오며, 이미 생성된 스트릭은 월드 공간에서 현재 노즐 쪽으로 조향된다. 여기에
  약한 접선 속도를 더해 완전한 나선이 아닌 느슨한 회전 곡선으로 빨려 들어간다. 판정 원뿔과
  VFX 외곽이 순간적으로 일치하지 않는 것은 의도한 유체 지연이다.
- **대기 가이드는 항상 희미하게 흐르고 클릭 순간에만 강해진다(2026-08-12).** 평상시 방출량은
  초당 7개, 알파는 작동 색상의 18%다. 클릭 직후와 포획 중에는 정상 방출량으로 올라가며,
  클릭 순간의 작은 펄스와 수거 순간의 밝은 펄스를 분리해 입력과 성공을 각각 읽게 한다.
- **대상별 흰색 리본은 보류한다(2026-08-12).** 현재는 물체와 노즐을 선으로 연결하지 않는다.
- **회오리는 얇은 흡입 링을 직접 그린다(2026-08-13).** 불완전한 원호 6개가 노즐 축을
  중심으로 회전하며 앞쪽 0.62m에서 흡입구 0.06m까지 이동한다. 접근할수록 반지름과 축 방향
  굴곡이 줄어들어 선이 흡입구로 빨려 들어간다. 외부 폭발 에셋은 사용하지 않는다.
- **환경 스트릭용 머티리얼만 런타임에 만든다.** 흡입 링은 NamuFX 복제 프리팹의 기존
  파티클 머티리얼과 붓터치 텍스처를 사용한다. Vendor 원본은 수정하지 않는다.

  (위 다섯 항목은 `VacuumConeVfx` 존재 당시의 기록이다 — 아래 참조로 이제 해당 스크립트 자체가
  없다. 판정 원뿔·노즐이라는 전제 자체가 바뀌었으므로 되살릴 때 그대로 재사용하지 말 것.)

- **`VacuumConeVfx`(원뿔 흡입 환경 흐름·회오리 VFX)를 삭제했다(2026-08-14).** `Vehicle/`의 흡입
  방식이 원뿔 다중포획에서 부채꼴 텔레키네시스(`VehiclePullAbility`)로 바뀌며 원뿔 자체가
  사라졌다. "대상별 흰색 리본은 보류한다(2026-08-12)" 결정도 이번에 뒤집혔다 — 부채꼴 사거리
  진입을 대상별로 알려야 하는 새 요구가 생겨, 리본 대신 `SuctionTarget.SetHighlighted`로
  구현했다(처음엔 흰 링, 같은 날 안에 보라색 맥동 이미션으로 다시 교체 — 아래 참조).
- **하이라이트는 "조준 중"에만 켜진다(2026-08-14).** 처음엔 부채꼴 사거리 상시 감시로 대상이
  들어오면 바로 켜졌지만, `Vehicle/`이 누르기 즉시 발동에서 "누르고 있는 동안 조준, 떼면 발동"
  으로 바뀌며 `SetHighlighted`를 부르는 시점도 방향키를 누르고 있는 동안으로 좁아졌다.
- **흰 `LineRenderer` 링을 보라색 맥동 이미션으로 완전히 교체했다(2026-08-14, 같은 날 두 번째
  개정).** "차라리 보라색 발광 쉐이더가 가시성이 더 좋겠다"는 사용자 판단 — 얇은 선보다 물체
  표면 자체가 빛나는 쪽이 운전 중 곁눈질로도 확실히 눈에 띈다. 구현은 새 셰이더를 짜지 않고
  렌더러당 `.material`(← `sharedMaterial` 아님)을 한 번 읽어 **그 오브젝트 전용 인스턴스**를
  만들고 `_EMISSION` 키워드를 켠 뒤 `_EmissionColor`를 토글하는 방식이다 — Trash 프롭 6종의
  머티리얼도, 테스트 큐브가 쓰는 URP 패키지 기본 `Lit.mat`(벤더 자산)도 전혀 건드리지 않는다.
  `__TrashOutline` 자식은 제외해 코랄 실루엣 외곽선은 그대로 둔다. 렌더러 인스턴스와
  `_EMISSION` 키워드는 한 번 만들면 계속 재사용한다(옛 링의 lazy-create-and-reuse와 같은 이유).
  `Vehicle_Prototype_Test.unity`의 기존 Bloom Volume(`VP_VehicleDriving.asset`, 문턱 0.9)에
  걸리도록 `Time.time` 기반 사인파로 세기를 맥동시킨다 — 사용자가 "맥동으로 시선을 더 끌자"를
  선택했다. 이 Bloom은 이 테스트 씬에만 있고 다른 씬에는 없다(2026-08-14 조사 확인) — 아직
  메인 게임플레이 씬에 이 능력 자체가 연결돼 있지 않으므로 지금은 이걸로 충분하다.
  - **색·세기 값은 시행착오로 잡았다, 계산만으로는 못 맞춘다.** 처음 `(0.62, 0.13, 1) × 4~9`로
    했더니 화면에서 완전히 흰색으로 날아갔다 — 오브젝트의 기존 albedo·조명 기여가 이미 밝은
    상태에 이미션을 더하니 R·G·B 세 채널이 전부 1.0을 넘어 디스플레이 클리핑되면서 색 정보가
    사라졌기 때문이다. **G 채널만 거의 0으로 유지**하면 R·B가 1.0에 클리핑돼도 G는 안 클리핑돼
    남아 있어 결과가 흰색이 아니라 마젠타/보라로 읽힌다 — `(0.7, 0.02, 1) × 1.5~3`로 낮추고서야
    해결됐다. 스크린샷으로 직접 확인했다. 색을 더 바꾸고 싶으면 **G를 0 근처로 유지**하는 것만
    지키면 되고, R·B·세기는 자유롭게 튜닝해도 된다.
  - **새 필드를 추가할 때 프리팹·씬에 이미 저장된 값은 C# 기본값을 안 따라간다.** 코드의
    `_glowIntensityMin/Max` 기본값을 4~9 → 1.5~3으로 고쳤지만, 이미 한 번 컴파일을 거쳐
    직렬화된 테스트 큐브 4개와 Trash 프리팹 8개는 여전히 옛 값(4~9)을 들고 있었다 — 전에
    `_sectorRadius`에서 겪은 것과 같은 함정. `SerializedObject`로 각 인스턴스·프리팹을 직접
    갱신해야 했다.
- **색을 마젠타/핑크에서 진짜 보라(자수정 톤)로, 세기는 어둡고 진하게 다시 조정했다
  (2026-08-14, 같은 날 세 번째 개정).** 사용자가 참조 이미지(어둡고 진한 보라 원석)를 주면서
  "더 어둡고 진하게"를 요청 — 두 가지를 동시에 고쳤다.
  - **색상 자체를 마젠타에서 인디고/바이올렛 쪽으로**: `(0.7, 0.02, 1)`(R이 B와 거의 같아
    마젠타로 읽힘) → `(0.35, 0.03, 0.85)`(R을 B보다 확실히 낮춰 진보라로 읽히게).
  - **"어둡게"는 이미션만으로는 안 됐다.** 세기를 아무리 낮춰도 물체 자신의 albedo·씬 조명
    기여가 이미 밝아서 옅은 라일락으로만 보였다 — 이미션은 기존 밝기 위에 **더할** 뿐 표면을
    어둡게 만들 수 없다. 그래서 `_baseColorDarken`을 추가해 하이라이트 중에는 `_BaseColor`
    자체를 `resting * 0.12`로 죽인다 — 밝은 표면 위에 옅게 물든 색이 아니라, 어두운 표면
    위에서 진하게 빛나는 색으로 읽히게 하는 게 핵심이다. 렌더러별 원래 `_BaseColor`는
    `EnsureGlowRenderers`에서 렌더러 배열과 나란히 캐싱해뒀다가 하이라이트가 꺼지면 되돌린다.
  - **Bloom 문턱(0.9)을 일부러 다시 밑돈다.** 세기 범위를 `1.5~3` → `0.5~1.2`로 낮춰 어떤
    채널도 1.0을 넘지 않는다 — Bloom에 걸려 번지는 순간 다시 클리핑되며 흰끼가 살짝 섞여
    "진하다"는 인상이 깨지기 때문에, 이번엔 순수 서페이스 이미션 색 자체로만 승부한다.
    더 화려한 번짐이 필요해지면 그건 세기를 다시 올리는 게 아니라 Bloom 프로필의 문턱을
    낮추는 쪽으로 접근해야 한다 — 문턱을 낮추면 이미 밝은 바닥 타일까지 같이 번지기 시작할
    수 있으니 전체 룩을 같이 봐야 한다(아직 안 함, Open 참조 가치 있음).
  - **`EnsureGlowRenderers`의 캐시 가드가 "한 번 실패하면 영원히 실패"였다.** `if (_glowRenderers
    != null) return;`는 씬 시작 직후 첫 프레임처럼 렌더러가 아직 준비 안 된 시점에 불려 빈
    배열이 캐시되면, 이후로는 null이 아니라서 다시는 못 채웠다 — 실제로 테스트 중 재현됐다.
    `_glowRenderers is { Length: > 0 }`로 바꿔 빈 배열은 재시도 대상으로 남긴다.
- **소비(포획 도착) 시 스케일 팝은 대상이 아니라 차량이 재생한다 — 대상 쪽 구현은 당일 되돌렸다
  (2026-08-14).** 처음엔 `SuctionTarget`에 `PlayConsumeEffect()`/`MMF_Player`를 넣어 먹힌
  물체 자신이 팝을 재생하도록 짰는데(Trash 프롭 8종 + 테스트 큐브 4개에 배선까지 완료), 실제로
  보니 사용자 의도는 "물체가 아니라 차가 커졌다 줄어드는" 것이었다. 그 구현은 전부 제거했다 —
  `SuctionTarget`은 다시 `_visualRoot` 스트레치와 하이라이트만 소유한다. 실제 구현·튜닝 노트는
  `../Vehicle/AGENTS.md`(`VehiclePullAbility._eatPopFeedback`) 참조.

## Open

- **Bloom 문턱을 낮춰 이미션에 진짜 빛 번짐을 주는 안은 보류했다.** 지금 세기 범위(0.5~1.2)는
  Bloom 문턱(0.9) 아래로 일부러 뒀다 — 서페이스 색 자체는 진하고 어둡지만 화면에 번지지는
  않는다. 더 화려한 연출을 원하면 Bloom 프로필의 threshold를 낮추는 실험이 필요한데, 그러면
  씬의 다른 밝은 표면(바닥 타일 등)도 같이 번지기 시작할 수 있어 전체 룩 튜닝이 딸려온다 —
  이번 범위 밖으로 미뤘다.

- **`Tests/Vacuum_Vfx_Test.unity`와 `Tests/VacuumVfxTestInput.cs`가 고아 상태다.** 검증 대상이던
  `VacuumConeVfx`가 삭제돼 씬을 열면 컴포넌트 참조가 끊어져 있다. 규칙 6번("기능이 사라지면
  테스트 씬도 같이 삭제")에 따라 `cm remove`로 정리해야 하지만, 씬 삭제는 이번 작업 범위 밖이라
  일단 남겨뒀다 — 다음에 이 폴더를 만지는 사람이 정리할 것.
