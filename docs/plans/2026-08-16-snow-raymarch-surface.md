# 눈 표면 — CPU 권위 / GPU 연출 분리와 v7 렌더러 이식

> **스펙** [2026-08-16-snow-raymarch-surface.md](../specs/2026-08-16-snow-raymarch-surface.md) ·
> **브랜치** `/main/snow-raymarch-surface` · **피처** `Assets/Game/InGame/Snow/`

## 0. 이 계획의 조직 원리 — 두 절반

|  | CPU 절반 (권위) | GPU 절반 (클라 전용 연출) |
|---|---|---|
| 무엇을 갖나 | **셀당 1바이트 높이(cm)** 그 이상 아무것도 | 높이에서 파생된 모든 것 — 로브·요철·실루엣·톤 |
| 어디서 도나 | 서버 + 클라, `-batchmode -nographics` 포함 | **클라만.** 그래픽 디바이스가 없으면 생성 자체를 안 한다 |
| 누가 읽나 | 감속·충돌·점수·복제 — **판정 전부** | **아무 판정도 읽지 않는다.** 읽으면 데디 서버에서 죽는다 |
| 파일 | `SnowField` · `SnowStage` · `SnowPlowBlade` · `SnowPlowLedger` · `SnowRepose` | `SnowSurfaceRenderer` · `Shaders/*` · 굽기 커널 |
| 이 브랜치에서 | **변경 0** | 전부 |

**이 분리가 v7 이식을 가능하게 한다.** v7 은 권위를 GPU 컴퓨트 버퍼에 뒀고 그것은 이 프로젝트에서 불가능하다
(데디 서버에 GPU 가 없다 — 루트 `AGENTS.md`). 그래서 시뮬레이션은 CPU 로 다시 썼다(cs:263). **반대로 v7 의
GPU 커널을 "연출"로 이식하는 데는 아무 제약이 없다** — 권위가 CPU 높이 하나에 있으므로, 클라가 그 높이를
읽어 무엇을 굽고 어떻게 마칭하든 서버·판정·복제와 무관하다.

### 경계를 지키는 규약 넷

1. **한 방향으로만 흐른다.** CPU 높이 → 업로드 → GPU 파생. **읽어오기(readback)는 없다.**
   `AsyncGPUReadback` 이 등장하는 순간 그 코드는 데디 서버에서 죽는다.
2. **GPU 파생은 순수 함수여야 한다** — 입력은 (CPU 높이, 정적 노이즈, 카메라)뿐. 시간에 누적되는 GPU 상태를
   만들지 않는다. 만들면 클라마다 화면이 갈라지고, 무엇보다 그것을 판정에 쓰고 싶어진다.
   ⚠ 이 프로젝트는 시간에 태운 형상이 무너진 실측이 있다(VFX 소용돌이가 80초 뒤 가로 고리로 붕괴).
3. **헤드리스에서는 존재하지 않는다.** RT·컴퓨트·머티리얼을 만들지 않는다. `SnowHeadlessTests` 가 지킨다.
4. **해상도가 두 축이다.** CPU 권위 셀(0.125m)과 GPU 파생 해상도(굽기 6.25cm, 마칭은 픽셀)는 **다른 값**이고
   서로 묶지 않는다. GPU 를 촘촘하게 올리는 것은 서버 비용·동기화 비용과 무관하다 — 그게 이 분리의 배당금이다.

## 1. 왜 지금 하는가 (게이트 재판정)

스펙은 "로브 반지름 대 프레임 예산을 아트와 정한 뒤"로 순서를 잡았다. 뒤집는다:

- 반지름은 스펙 §7 이 **손질 순서**까지 정해둔 파라미터다(① 거리 페이드 ② 거리 LOD ③ 반지름).
  아트가 맨손으로 고를 숫자가 아니라 **측정 후 조이는 값**이다.
- 스파이크 실측(`6.13` / `7.83 ms`)은 **눈만 있는 씬** 값이다. 우리 씬은 드로우콜 631·삼각형 1.24M 이라
  재측정 없이는 아트에 줄 숫자가 없다.
- 오늘 나온 relax 실측이 우선순위를 바꿨다 — **CPU 정착이 프레임당 2.7ms.** 렌더러 증분(`+1.70ms`)보다 비싸다.
  아트에 물을 질문은 "반지름 몇?"이 아니라 **"눈에 총 몇 ms 를 주는가"** 다.

## 2. 태스크

### Task 1 — 프록시 박스 (GPU 절반)

`SnowPanelBuilder` 가 그리드 메시 대신 **프록시 박스**를 만들 수 있게 한다. 그리드 경로는 A/B 를 위해 남긴다
(인스펙터 열거형 `Grid` / `ProxyBox`).

- 박스 높이는 `_maxDepth` + 여유. 바운즈가 최대 깊이를 담아야 컬링이 표면을 자르지 않는다.
- **검증**: 삼각형 수와 바운즈를 콘솔에 찍는다. 그리드 658k → 박스 12 삼각형.

### Task 2 — 마처 (⚠ 게이트)

`Shaders/SnowRaymarch.shader` + `.hlsl`. 3패스(ForwardLit / ShadowCaster / DepthOnly)가 **같은 마칭 함수**를 쓰고
`SV_Depth` 를 쓴다. 로브는 아직 없다.

스펙 §2 가 "생사를 가른다"고 한 것은 **스텝 전략**이다. 균일 스텝은 실패한다 — 스파이크에서 광선 0.56%가
표면을 관통했고, 그것을 **셰이더를 짜기 전에 수치 하네스가 먼저 잡았다.**

- **검증(기준 2)**: 마칭 프로브 — 평균 스텝·p95·예산 소진 비율. **관통 0.**
- **검증(기준 1·3)**: 정점 변위와 같은 프레임 A/B 캡처. 실루엣·그림자·차량 교차가 어긋나면 멈춘다.
- ⚠ 관통이 남으면 로브를 얹기 전에 §2 로 돌아간다.

### Task 3 — 로브 굽기 커널 (v7 GPU 이식의 본체)

`Shaders/SnowLobeBake.compute` + `SnowSurfaceRenderer` 의 굽기 경로. 구 격자를 **높이 기여**로 바꿔
필드 2배 해상도(6.25cm) R8 한 장에 굽는다. 창은 dirty rect 주변 240×240 텍셀 전후, 디스패치 1회.

- **스텝당 연산을 늘리지 않는다** — 마처는 **1탭**만 읽는다. 스텝마다 해시 9개를 돌린 판이 `15.44ms`,
  구운 판이 `7.83ms` 였다. 승리는 상한이 아니라 **스텝당 연산 제거**에서 나왔다(스펙 §3). 순서를 뒤집지 않는다.
- 굽기는 규약 2 를 지킨다 — 입력은 CPU 높이와 정적 해시뿐, 프레임 간 누적 없음.
- **검증(기준 10)**: `_lobeRadius = 0` 이면 Task 2 기준선을 **비트 단위로** 재현.
- **검증(기준 9)**: 치운 자리에서 로브 0 — 맨땅에 뜬 로브가 보이면 실패.
- **검증(기준 8)**: 로브가 읽히는가. 판정 기준은 스펙 §3 의 두 비교 이미지.

### Task 4 — A/B 스위치와 헤드리스 안전

`SnowSurfaceRenderer` 에 렌더러 선택. 같은 씬에서 두 방식을 한 프레임씩 캡처할 수 있어야 한다.

- **검증(기준 6)**: 같은 카메라 포즈 두 캡처.
- **검증(기준 7)**: `-batchmode -nographics` 에서 굽기 RT·컴퓨트가 **생성되지 않는다.**
  `SnowHeadlessTests` 에 로브 경로 단정을 추가한다 — 경계 규약 3 을 테스트로 굳히는 자리다.

### Task 5 — 측정 (⚠ 게이트: 아트에 줄 숫자)

스펙 §7 프로토콜을 그대로 — **런 내부 연속 14샘플 평균.** 단일 샘플로는 30% 이내 대안을 순위 매길 수 없다
(같은 설정이 `16.49` / `25.26 ms` 로 읽힌 실측). `meanSteps` 는 편차 0 이라 가장 좋은 판별자다.

조건 넷: 로브 끄기/켜기 × 카메라 낮음(1.15m)/게임 시점. 대상은 **`WinterVillage_ConceptMap`**(실제 부하).

- **검증(기준 4)**: 로브 포함 **4~5 ms** 목표. 넘으면 스펙 §7 손질 순서대로 조인다.
- 산출물: 조건별 표 + A/B 캡처 → `Snow/AGENTS.md`.

### Task 6 — 회귀

- **기준 5**: `Dust_Look_Test` 캡처로 먼지 회귀 0.
- EditMode 60 / PlayMode 14 유지(헤드리스).
- `Snow_Plow_Test` 보존이 그대로 `mass=0.0000L ok` — **렌더러 교체가 권위를 건드리지 않았다는 증거**이고,
  더 강한 증거는 diff 다: CPU 절반의 변경 줄 수가 **0** 이어야 한다.

## 4. 범위 밖 (스펙 §6)

캐주얼 아트 톤(밴드 수·그림자 색·노출 — 별 체크인), 눈덩이·적재 원장, coarse-max 밉 피라미드,
스크린스페이스 스무딩(실측 후 기각), 경사면 위의 눈.

## 5. 이 계획이 스펙에 더하는 제약

- **기존 `SnowSurface.shader` 를 지우지 않는다.** A/B 가 기준 6이고, 관통·성능이 안 잡히면 돌아갈 곳이 필요하다.
  제거는 측정이 끝난 뒤 별 체크인.
- **CPU 절반은 한 줄도 만지지 않는다.** 위 표의 왼쪽 열 파일들의 diff 가 0 인 것이 이 브랜치의 합격 조건 중 하나다.
- **에디터를 켠 채 브랜치를 전환하지 않는다**(스펙 §7 — 전체 리임포트).
