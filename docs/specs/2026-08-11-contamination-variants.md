# 오염 배리언트 — 설계

> **작성일** 2026-08-11 · **브랜치** `/main/contamination-variants` · **피처** `Assets/Game/InGame/Dust/`

흙먼지 하나뿐인 오염을 **오염 종류 × 바탕 표면** 두 축으로 늘리고, 한 표면에 오염이 **층으로 겹칠** 수 있게 하는 구조를 정한다.

**이 문서는 스펙이다.** 지금 짓는 것은 불투명 표면 위의 오염 **1층**뿐이고, 나머지는 자리만 잡는다.
그래서 성공 기준은 하나다 — **1층 구현이 3층으로 가는 문을 닫지 않을 것.**

> **이 문서의 이미지는 아트 타겟이지 명세가 아니다.** 무엇을 겨냥하는지를 보여줄 뿐, 무엇이
> 만들어졌다는 증거도 설계가 동작한다는 증거도 아니다. 실제 셰이더 렌더가 나오면 버린다.

> `images/dust-target-grain.png`와 `images/verify/tiling_near_on.png`를 레퍼런스로 붙였다.

> 주황에 가까우니 **톤은 참고하지 말 것** — 읽어야 할 것은 배치와 대비뿐이다.

## 0. 범위

| | 지금 짓는다 | 스펙만 잡는다 |
|---|---|---|
| 오염 층 | 1층 | 최대 3층, 순서 있음 |
| 렌더 모드 | 불투명 | 투명(유리 물때) |
| 표면 | 바닥 | 벽·유리·카펫 |
| 오염 종류의 런타임 데이터 | 없음 | ScriptableObject 자리만 |
| 청소의 맛(VFX·사운드·청소도) | 없음 | 별건 |

오염 대상 메시는 스테이지 전체가 아니라 **따로 지정된 집합**이고, 당장은 바닥뿐이다.

## 1. 두 축

오염은 두 축으로 늘어난다. 두 축이 바꾸는 것이 다르다.

- **바탕 표면** — 깨끗한 상태의 albedo·노멀·smoothness. **닫힌 표준이다.** 표면을 아무리 늘려도 파라미터가 늘지 않고 텍스처 슬롯만 갈린다.
- **오염 종류** — 이 피처가 직접 만든 합성 로직. **열려 있다.** 젖은 정도나 흐른 방향이 필요한 오염이 들어오면 파라미터가 또 붙는다.

현재 `DustSurface.shader`의 프로퍼티 26개가 이 비대칭을 그대로 보여준다: 표면 5개, 오염 21개. 이 격차는 시간이 갈수록 벌어지지 좁아지지 않는다. 아래의 계층 방향은 전부 여기서 나온다.

![같은 오염이 타일과 나무 위에](../images/dust-target-surface-matrix.png)

왼쪽 타일, 오른쪽 나무. **오염은 같고 바탕만 다르다.** 이 차이가 셰이더가 아니라 `_BaseMap`·`_NormalMap` 교체로 끝나야 한다는 것이 §5와 §6의 근거다.

## 2. 층 합성 모델

### `ComposeDust()`는 이미 접기(fold)다

```hlsl
ComposeDust(half3 cleanAlbedo, half cleanSmoothness, half3 cleanNormalTS, ...)
    -> DustSurfaceResult { albedo, smoothness, normalTS }
```

반환 구조체의 세 필드가 첫 세 인자와 정확히 대응한다. 그래서 층 쌓기에 **새 함수도 새 개념도 필요 없다.**

```hlsl
r = { cleanAlbedo, cleanSmoothness, cleanNormalTS };            // 깨끗한 바닥
r = ComposeDust(r.albedo, r.smoothness, r.normalTS, d0, ...);   // 층 0 (아래)
r = ComposeDust(r.albedo, r.smoothness, r.normalTS, d1, ...);   // 층 1
r = ComposeDust(r.albedo, r.smoothness, r.normalTS, d2, ...);   // 층 2 (위)
```

이번 브랜치는 이 체인의 **첫 줄만** 짓는다.

### 순서는 슬롯 순서, 오써링 시점에 고정

슬롯이 낮을수록 아래다. 런타임에 순서가 바뀔 이유가 없으므로 셰이더에 순서 분기를 넣지 않는다.

### 걷어내면 아래가 드러나는 것은 공짜다

위층의 `d`가 0이면 그 `cover`가 0이 되고 `lerp(아래결과, 위, 0)`이 아래 결과를 **그대로** 돌려준다. 먼지를 걷어내면 아래 기름때가 나오는 동작에 별도 코드가 없다.

### 오써링 규칙 — 아래층일수록 밝고 약하게

**층 모델에는 청소의 맛을 뒤집는 함정이 있다.** 먼지를 걷어냈는데 그 아래 기름때가 더 어두우면 화면이 더 깨끗해지지 않고, 기획서가 핵심 보상이라고 한 청소 전후 대비(`Game_Concept.md:116`)가 거꾸로 뒤집힌다.

그래서 층 순서를 정할 때 **아래로 갈수록 밝고 옅게** 간다. 그래야 한 번 닦을 때마다 화면이 단조롭게 깨끗해진다. 이건 머티리얼을 다 만든 뒤에 발견하면 전부 다시 잡아야 하므로 순서를 정하는 시점에 지킨다.

![아래층이 어두울 때와 밝을 때](../images/dust-target-layer-order.png)

**왼쪽이 금지하는 배치다.** 같은 먼지를 같은 모양으로 닦았는데, 왼쪽은 아래에서 짙은 기름때가 올라와 닦은 자리가 주변보다 더 무겁고 더러워 보인다 — 청소했는데 화면이 나빠진다. 오른쪽은 아래가 밝아 닦은 자리가 그대로 성과로 읽힌다. 층 순서를 정하는 사람이 봐야 할 그림은 이 한 장이다.

닦임 표시 자체는 이미 있다 — `_EdgeRim`이 `cover` 0.5에서 최대가 되므로 갓 드러난 경계가 층마다 밝게 뜬다. 층별로 자동으로 걸린다.

## 3. 마스크 규약 확장

기존 규약(`Dust/AGENTS.md`)에서 **채널만** 넓힌다. 나머지는 그대로다 — 메시 UV0, `1 = 더러움`, 지우기 전용, `_DirtMask` 한 슬롯.

| 층 수 | 채널 | 포맷 | 메모리 |
|---|---|---|---|
| 1 (지금) | R | `R8` | 1배 |
| 2 | R / G | `RG16` | 2배 |
| 3 | R / G / B | `ARGB32` | 4배 |

`Dust/AGENTS.md`가 약속한 대로 **`SampleDirt()` 한 곳만** 바뀐다.

**마스크는 층 수와 무관하게 1회만 샘플한다.** 텍스처 샘플 하나가 `float4`를 돌려주므로 한 번 읽고 채널을 스위즐한다. 층마다 샘플하면 이유 없이 3배가 된다.

### 층 수는 유니폼이 아니라 셰이더 키워드

층마다 albedo·노멀·러프 3장을 샘플하므로 3층이면 9장, 확률적 타일링을 켜면 **27장**이다. 유니폼 분기로는 샘플이 사라지지 않지만 키워드는 진짜로 사라진다. 대부분의 바닥이 1층일 것이므로 흔한 경로가 싸진다.

```
#pragma shader_feature_local_fragment _ _DIRT_LAYERS_2 _DIRT_LAYERS_3
```

배리언트는 3종, 기존 `_STOCHASTIC_TILING`과 곱해 **6종**.

이것은 §7에서 "오염 종류를 키워드로 나누지 않는다"고 한 것과 모순되지 않는다. 오염 **종류**는 같은 수식에 다른 숫자라 키워드가 벌 것이 없고, 층 **수**는 샘플 수 자체가 달라진다.

### 아틀라스와의 상호작용

`Dust/AGENTS.md`의 미결 사항인 **마스크 아틀라스**와 곱해진다. 채널 4배는 아틀라스가 결정될 때 그 비용에 그대로 곱해지므로, **아틀라스를 설계하는 시점에 층 수가 이미 정해져 있어야 한다.**

지금 당장은 압박이 아니다. 오염 대상이 바닥 몇 장이면 4배도 작은 수의 4배다. 다만 `Dust/AGENTS.md`는 *"오염 가능한 표면은 스테이지의 대부분이 될 것"*으로 적고 있어 현재 상태(바닥뿐)와 어긋난다. **둘 중 어느 쪽이 맞는지는 아틀라스를 설계할 때 먼저 확정한다.**

## 4. 파라미터 조직

### 배열은 막혀 있다

셰이더 `Properties` 블록은 배열을 지원하지 않는다. `float4 _LayerTint[3]`은 CBUFFER에 선언은 되지만 인스펙터로 편집할 수 없고 `Material.SetVectorArray`가 필요하다. 지금은 C#을 넣지 않으므로 **접두사를 붙인 평평한 프로퍼티**가 실질적인 유일한 선택지다.

### 무엇이 층별이고 무엇이 공통인가

| 구분 | 개수 | 프로퍼티 |
|---|---|---|
| 표면 (층과 무관) | 5 | `_BaseMap` `_BaseColor` `_BaseMapTiling` `_NormalMap` `_Smoothness` |
| 오염 공통 (1벌) | 5 | `_DirtMask` `_MacroTiling` `_UseStochasticTiling` `_StochasticContrast` `_DissolveNoise` |
| 층별 (`_Layer0_`) | 16 | `_Amount` `_AlbedoMap` `_NormalMap` `_RoughMap` `_ColorA` `_ColorB` `_Smoothness` `_RoughInfluence` `_GrainTiling` `_GrainStrength` `_DissolveTiling` `_EdgeSoftness` `_ThinOpacity` `_FullDirtAt` `_EdgeRim` `_EdgeRimColor` |

합이 26으로 현재 프로퍼티 수와 같다. 층 3개면 5 + 5 + 48 = 58개.

공통으로 남긴 근거:

- **디졸브 노이즈 텍스처**는 층이 공유하고 **타일링만 층별**로 어긋내면 패턴 겹침이 풀린다. 샘플러도 아낀다.
- **확률적 타일링**을 층별 키워드로 두면 배리언트가 곱으로 터진다.
- **매크로 색 변화**는 바닥 전체에 걸친 저주파라 층마다 나눌 실익이 적다.

`_DirtAmount`가 층별로 간 이유: 층마다 전체 양을 따로 잠글 수 있어야 **도구별 개별 제거**가 나중에 성립한다.

### 접두사는 층별로 갈릴 것에만 지금 붙인다

셰이더 프로퍼티를 나중에 이름 바꾸면 머티리얼에 저장된 값이 날아간다. `DustSurface`를 쓰는 머티리얼이 2장뿐인 **지금이 가장 싸다.** 공통으로 남는 5개는 이름을 바꾸지 않으므로 그대로 둔다 — 이름 자체가 공통인지 층별인지를 말해준다.

**마이그레이션 순서** (구현 계획에서 이 순서를 지킨다):

1. `M_Dust_Granular`의 현재 값 16개를 기록한다
2. 셰이더 프로퍼티 이름을 바꾼다
3. 값을 다시 넣고 `Tests/Dust_Look_Test.unity`에서 눈으로 확인한다

`M_Dust_Film`은 `Dust/AGENTS.md`가 "참조가 없어지면 삭제"라고 적어둔 비교용이므로 마이그레이션 대상에서 뺀다. 값이 날아가도 잃을 것이 없고, 오히려 삭제 시점을 앞당기는 근거가 된다.

### 샘플러 한도

지금 텍스처 7장이다. 층 3개면 층별 맵 9장 + 베이스 2 + 마스크 1 + 디졸브 1 = **13장**으로 모바일 한도 16에 아슬아슬하다.

완화책은 **채널 패킹**을 우선한다 — albedo(RGB) + rough(A)를 한 장으로 합치면 층당 2장이 되어 10장. 이미 있는 `docs/images/generate_dust_textures.py`를 늘리면 되고 C#이 필요 없다.

`Texture2DArray`도 샘플러를 줄이지만 에셋을 만들려면 에디터 스크립트가 필요하고 모든 슬라이스가 같은 해상도·포맷이어야 한다. 채널 패킹이 막힐 때의 2안이다.

## 5. 머티리얼 계층

**부모 = 오염 조합(층 구성), 자식 = 표면.**

```
M_Dust                    부모 — 오염 룩과 마스크 규약을 여기서 잠근다
 ├ M_Dust_OnTile          자식 — 표면 5개만 오버라이드
 └ M_Dust_OnWood
M_GreaseDust              (나중) 2층. 이름은 아래→위 순서로 읽는다
 └ M_GreaseDust_OnTile
```

지금은 조합이 1층이라 "오염 종류"와 같다. 그래서 지금 지은 것이 나중에 그대로 확장된다.

잠금의 기준은 **정체성이냐 분포냐**다.

| | 프로퍼티 | 이유 |
|---|---|---|
| **부모에서 잠근다** | 오염 룩 — 맵 3장, 틴트 2개, smoothness, 그레인 2개, 디졸브 타일링, 엣지 4개 | "이 오염이 무엇인가"를 정한다. 표면 배리언트가 몰래 흔들면 같은 먼지가 바닥마다 달라 보인다 |
| **자식·인스턴스가 정한다** | `_BaseMap` `_BaseColor` `_BaseMapTiling` `_NormalMap` `_Smoothness`, 그리고 `_DirtMask` `_Layer0_Amount` | 앞의 5개는 표면. 뒤의 2개는 "그 표면에서 얼마나, 어디가" 더러운지다 |

**`_DirtMask`를 잠그면 안 된다.** `DustPaintTarget.cs:39`가 머티리얼의 `_DirtMask`를 읽어 RenderTexture의 시작 상태로 굽는다 — 즉 이 슬롯은 **초기 오염 분포**다. 잠그면 주방과 복도가 똑같은 자리에서 더러워지기 시작한다. 같은 이유로 `_Layer0_Amount`(그 층의 전체 양)도 자식이 정한다.

머티리얼 배리언트는 **Unity Project 창에서만** 만든다. 루트 `AGENTS.md`가 YAML 손편집을 금지하고, `m_Parent`는 손으로 쓸 필드가 아니다.

### 왜 이 방향인가

| 근거 | 내용 |
|---|---|
| 편집 빈도 | `Dust/AGENTS.md`에 기록된 결정 10개가 **전부 오염 룩 튜닝**이다. 잦은 편집을 부모 한 곳에 모아 모든 표면에 전파시킨다 |
| 개수 비대칭 | 오염 종류(N)는 적고 표면(M)은 많다. **N < M**이므로 표면 편집이 건드리는 자식 수가 오염 편집보다 적다 |
| 잠금 지점 | 오염 룩을 잠글 단일 지점이 생긴다. 뒤집으면 그런 지점이 없다 |

## 6. 셰이더 분할 기준

**렌더 모드가 바뀔 때만 갈라진다.**

- 불투명 전부 → `DustSurface.shader`
- 유리 물때 등 투명 → `DustSurfaceTransparent.shader` (나중)

둘 다 `DustSurface.hlsl`을 공유한다. `ComposeDust()`는 오염 종류도 렌더 모드도 모르므로 그대로 재사용된다. 표면이 늘어난다고 셰이더가 늘지 않는다 — 표면은 텍스처 슬롯이다.

## 7. 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| **부모 = 표면, 자식 = 오염** | 오염 파라미터 16개가 표면마다 복제된다. 그레인 타일링을 3→4로 바꾸면 표면 수만큼 손봐야 하는데, 그 편집이 지금까지 가장 잦았던 편집이다 |
| **오염 종류를 셰이더 키워드로 분기** (`_GREASE` `_MOLD`) | SRP Batcher는 셰이더 배리언트 단위로 배칭한다(`Dust/AGENTS.md`). 키워드는 배리언트를 배로 늘리고 배칭을 쪼갠다. 그런데 기름때·음료 얼룩은 수식이 아니라 **숫자만** 다르다 — `_Layer0_Smoothness`를 올리고 `_Layer0_EdgeSoftness`를 낮추면 끝이다. 벌 것이 없는데 비용만 낸다 |
| **버텍스 컬러로 오염 표현** | 해상도가 버텍스 밀도다. 픽셀 단위 지우기가 이 시스템의 핵심인데 임의의 윤곽을 표현할 수 없다 — `Dust/AGENTS.md`가 counting grid를 기각한 이유와 같다. 버텍스 컬러가 쓸모 있는 자리는 **어디에 무슨 오염이 깔릴지 정적 배치를 굽는 용도**이고, 지워지는 상태는 계속 마스크가 들고 있어야 한다 |
| **층별 파라미터를 배열로** | `Properties` 블록이 배열을 지원하지 않는다. §4 참조 |
| **오염을 별도 머티리얼/데칼 레이어로** | 드로우 콜이 층 수만큼 늘고, URP 데칼은 `Dust/AGENTS.md`에서 이미 기각됐다 |

## 8. 비워두는 자리

지금 짓지 않지만 구조가 막지 않아야 하는 것들.

| 항목 | 자리 |
|---|---|
| 오염 종류의 런타임 데이터 | 도구 적합성·제거 속도·청소도 가중치를 갖는 ScriptableObject. 루트 `AGENTS.md`의 "두 번째 호출부에서 추상화" 규칙에 따라 두 번째 소비자가 생길 때 만든다 |
| 투명 셰이더 | `DustSurfaceTransparent.shader`, `DustSurface.hlsl` 공유 |
| 표면별 특수 셰이딩 | 카펫의 깊이감 등. 렌더 모드가 같으면 셰이더를 나누지 않는다는 §6이 먼저 깨지는지 확인할 것 |
| 마스크 아틀라스 | `Dust/AGENTS.md`의 기존 미결 사항. §3의 채널 배수가 여기 곱해진다 |
| 버텍스 컬러로 초기 분포 | 지금은 초기 오염 분포가 `_DirtMask` 텍스처라 시작 패턴이 다를 때마다 텍스처가 한 장씩 든다. 버텍스 컬러 RGB를 층 0/1/2의 시작량으로 읽으면 텍스처 없이 메시마다 다른 분포가 나온다. **지워지는 상태는 계속 마스크가 들고 있는다** — 버텍스 컬러는 굽는 용도지 지우는 용도가 아니다(§7) |
| 청소의 맛 | VFX·사운드·청소도 집계. `cover`가 층별로 이미 셰이더 안에 있으므로 꺼내 쓸 값은 준비돼 있다 |

## 9. 뒤집는 조건

- **계층 방향** — 표면 수가 오염 종류 수보다 적어지거나, 바탕 머티리얼을 오염되지 않는 오브젝트와도 공유해야 할 때. 그때는 §5를 뒤집는다.
- **층 수 3** — 4층이 필요해지면 채널이 모자란다(A는 예비). 마스크를 두 장으로 늘리기 전에 층 수 자체를 다시 따진다.
- **오염 종류 키워드** — 어떤 오염이 `ComposeDust()`로 표현되지 않는 **수식**을 요구할 때. 숫자로 안 되는 것이 확인된 뒤에만 키워드를 연다.
