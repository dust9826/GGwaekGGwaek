# 선물 공장 배송 의뢰 시스템

## 목표

한 마을의 여러 선물 공장 사이로 배송 트럭 의뢰가 계속 들어온다. 플레이어는 트럭이 갈 도로의 눈을
치워야 한다. 눈 때문에 트럭이 연속 제한 시간 이상 멈추면 의뢰가 취소되고, 최종 공장에 도착하면
계획된 도로 길이에 비례한 점수를 받는다.

## 채택한 구조

- 기본 의뢰 생성 간격 15초, 기본 눈 정차 취소 시간 5초. 둘 다 런타임 파라미터다.
- 의뢰는 두 공장으로 시작하되 방문 공장 목록을 가져 여러 공장 순차 방문을 지원한다.
- 도로는 폭을 가진 거리 기반 중심선 곡선이다. 직선·곡선·S자·ㄱ자를 같은 데이터로 표현한다.
- 눈 판정은 `SnowField` CPU 격자만 사용한다.
- 넓은 도로에서는 트럭 폭의 연속된 빈 통로를 찾아 좌우로 피한다.
- 여러 트럭은 도로에 함께 진입한다. 충돌이 예상되고 비켜갈 폭이 없을 때만 우선순위를 고정하고
  낮은 쪽이 명시적 대피 지점, 넓은 빈 구간, 빈 옆길 순으로 후진한다.
- 점수는 실제 이동 거리가 아니라 계획 경로 중심선 길이로 계산한다.

## 상태

의뢰: `Active`, `Completed`, `Cancelled`.

트럭: `Driving`, `SnowBlocked`, `YieldReversing`, `YieldWaiting`, `ResumeRoute`, `Completed`,
`Cancelled`.

`SnowBlocked`일 때만 연속 정차 시간이 증가한다. 눈이 치워지면 0으로 초기화한다.

## 교통 우선순위

1. 현재 좁은 구간의 출구에 더 가까운 트럭
2. 구간에 더 깊이 진입한 트럭
3. 더 오래된 의뢰
4. 의뢰 ID

한 조우의 결과는 두 트럭이 완전히 지나갈 때까지 바꾸지 않는다.

## 점수

`round(전체 계획 도로 길이 × 미터당 점수)`. 중간 공장, 후진, 횡회피에는 별도 점수가 없고
취소된 의뢰는 0점이다.

## 맵 저작 순서

1. 교차로와 공장 진입점에 `DeliveryRoadNode`를 놓고 맵 안에서 고유한 ID를 준다.
2. 두 노드 사이마다 `DeliveryRoadSegment`를 만들고 중간 월드 제어점, 주행 가능 폭, 코너 반경을 설정한다.
3. 건물에 `DeliveryFactory`를 붙여 대응하는 도로 노드와 선택적인 정차 Transform을 연결한다.
4. 후진 장소를 반드시 고정하고 싶은 병목에는 `DeliveryYieldPoint`를 놓는다. 없어도 넓은 후방 구간과
   점유되지 않은 옆길을 런타임에 탐색한다.
5. `DeliveryRoadNetwork`, `DeliveryTrafficController`, `DeliveryDirector`, `SnowStage`와 트럭 프리팹을
   연결하고 `TryValidate` 오류가 없는지 확인한다.

`Assets/Game/InGame/Delivery/Tests/Delivery_RequestFlow_Test.unity`는 직선·곡선·ㄱ자·S자 도로와
막다른 옆길을 모두 포함한 저작 예시다. 테스트 씬이므로 Build Settings에는 넣지 않는다.
